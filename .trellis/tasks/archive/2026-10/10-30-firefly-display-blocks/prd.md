# Firefly Markdown 展示块与图文编排

## 目标与用户价值

为 Firefly 增加统一的 `firefly` 围栏代码块展示扩展。作者继续使用普通 `.md` 文件，通过少量声明描述资源、展示方式和关联内容；网站将这些块转换为图片、链接卡片、原生音视频播放器或图文组合。

核心价值是同时满足文章编排与文件流通：在 Firefly 中获得增强展示，在其他 Markdown 查看器中仍能打开完整源文件，Firefly 块以代码块保留，其他正文照常阅读。增强展示不要求作者维护组件代码、CSS 或另一份移动端内容。

## 背景与现状证据

### 编排目标与内容边界

- 图片可左右交替，相关文字在图片旁环绕，超过图片高度后恢复全宽；网站统一负责间距和窄屏堆叠。
- 正文应以静态 HTML 持续可读，不因滚动、媒体加载或增强初始化而先隐藏再显示。验收使用项目自有的合成内容与媒体。

## 已确认的产品模型

### 作者的心智

“插入一个展示块，说明展示什么、资源在哪里、如何摆放；需要组合编排时，把图片与关联文字放在同一个块内。”

| 概念 | 作者提供的内容 | Firefly 负责的行为 |
| --- | --- | --- |
| 展示类型 | `type`，如图片、链接、播放器、图文组合 | 选择对应展示能力 |
| 资源 | 本地相对路径或适合该类型的外部 URL | 解析引用并生成展示及可用的资源链接 |
| 内容 | 替代文本、图注或图文组合的正文 | 正确展示文本，按约定解析 Markdown |
| 编排 | 图左、图右、图上 | 尺寸、间距、环绕范围和窄屏适配 |

这里的“操作”是声明展示意图，不是执行命令、脚本或任意组件代码。

### 编排范围

- 一个 `composition` 块是一个完整的图文单元：一张图片或 GIF，以及与它一起编排的 Markdown 正文。
- 需要编排的局部进入块内；普通文章正文继续在块外书写，不要求整篇文章迁入 YAML。
- 不采用“影响后面 N 个段落”、按空行推断范围或让浮动延续到未知位置的写作规则。
- 简单图片、链接或播放器块不要求 `content`。

## 首版范围

| 类型 | 首版结果 | 范围说明 |
| --- | --- | --- |
| `image` | 图片，可附替代文本及图注 | GIF 作为图片资源使用，不单设 GIF 类型。 |
| `link` | 可点击的外部网页链接卡片 | 有作者提供的信息时展示标题/描述；拿不到远端元信息也必须保留可用链接。 |
| `video` | 浏览器原生视频播放器及资源入口 | 面向可直接播放的视频资源，不把网页详情页 URL 当成视频直链。 |
| `audio` | 浏览器原生音频播放器及资源入口 | 面向可直接播放的音频资源。 |
| `composition` | 图文组合 | 首版组合媒体为图片/GIF，支持 `image-left`、`image-right`、`image-top`。 |

首版以文章和页面的 `firefly`、`semantic` 两种表现形式及 `default`、`paper` 正文主题为验收面。Memo 特有的时间线、摘要和阅读动作不在本次默认扩展范围内，接入时不能无意改变其现有行为。

## 写作语法与示例

以下是本任务实现的写作接口。围栏语言固定为 `firefly`，块内采用 YAML；`type` 表示展示类型。

### 单独图片或 GIF

````markdown
```firefly
type: image
src: ./assets/illustration.png
alt: 由圆形和矩形组成的原创几何插图
caption: 用于排版测试的原创插图
```
````

`src` 为资源引用，`alt` 为图片替代文本，`caption` 为可选的可见图注。两者语义不同，不把图注和替代文本混为一个字段。普通图片仍可以使用已有的 `![描述](地址)`，不要求迁移。

### 图左文右

````markdown
这里是普通正文。

```firefly
type: composition
layout: image-left
media:
  type: image
  src: ./assets/illustration.png
  alt: 由圆形和矩形组成的原创几何插图
content: |
  这是一组用于测试排版的原创说明。图片放在左边，相关文字从右边开始。

  可以继续添加段落，观察文字超过图片高度后恢复全宽的效果。
```

这里恢复普通正文，不受上一张图片影响。
````

| `layout` | 桌面端效果 | 窄屏效果 |
| --- | --- | --- |
| `image-left` | 图片靠左，文字从右侧环绕；超过图片高度后恢复组内全宽 | 图片在上，正文在下 |
| `image-right` | 图片靠右，文字从左侧环绕；超过图片高度后恢复组内全宽 | 图片在上，正文在下 |
| `image-top` | 图片在上方居中，正文在下方 | 图片在上，正文在下 |

居中图指上下排列，不要求文字同时分布在图片左右。`content: |` 中的内容按 Markdown 解析，保留段落、强调、链接等正文语义。

### 链接卡片

````markdown
```firefly
type: link
url: https://example.com/article
title: 延伸阅读
description: 与本段内容有关的外部文章。
```
````

`url` 表示跳转目标。标题、描述用于可读展示，不要求作者配置远程抓取服务。只有 URL 的最小写法也必须可用，元信息不能成为文章构建或阅读的外网前置依赖。

### 原生音视频

````markdown
```firefly
type: video
src: ./assets/test-pattern.mp4
caption: 本地生成的视频测试图案
```

```firefly
type: audio
src: ./assets/test-tone.mp3
caption: 本地生成的合成测试音
```
````

播放器由读者主动操作。媒体格式是否可以解码仍取决于浏览器；格式不受支持或资源无法播放时，读者仍有可访问的资源链接，不阻断前后正文。

## 产品需求

### R1 — 统一的声明入口

- 用同一种 `firefly` 围栏扩展承载首版展示类型，避免为每种媒体引入互不相关的写作语法。
- 插件根据 `type` 选择能力，具备后续新增类型或平台适配器的扩展位置；本次不要求插件市场或用户编写插件。
- 该“插件”指内容解析和展示扩展，不预先等同于仓库现有的服务插件开关、部署或公共访问协议。
- 非 Firefly 围栏保持原有代码展示；原有 Mermaid、代码高亮和普通 Markdown 行为保留。

### R2 — 文件流通与诚实降级

- 源文件保持普通 Markdown，不要求转换成 MDX、导入组件或生成另一份专用文章。
- 不支持本扩展的查看器展示原始代码块；明确不承诺其自动展示图文或播放器。块内正文仍存在，但会与 YAML 一起显示，不承诺与普通段落相同的阅读效果。
- 其他正文、标题、链接和普通图片不受扩展支持情况影响。
- 本地资源随文档一同流通；单独复制 `.md` 不等于资源内嵌。相对路径以作者文档位置为语义基准，发布后解析必须正确，不能误相对于页面 URL 查找原始文件。
- 无需为所有块额外手写一份重复的降级正文。

### R3 — 有界的图文组合

- 支持上述三种编排；横向位置由作者声明，默认宽度、间距和移动端断点由网站统一管理，首版不要求作者指定像素或比例。
- 环绕只作用于当前组合；连续多个左右交替块、之后的段落和下一节标题各自保持正确位置。
- 正文可以超过图片高度并恢复全宽，不能只做成固定的等高两列。
- 图文组合的源阅读顺序为图片及其说明、关联正文；窄屏据此堆叠，作者无需维护移动端版本。

### R4 — 媒体与链接的语义

- 图片、GIF、网页卡片、视频直链、音频直链按显式类型处理，不用“所有 URL 都自动嵌入”替代作者意图。
- 图片替代文本、可见图注和组合正文分别保留，正文中的 Markdown 链接可正常访问。
- 链接卡片即使没有封面、标题抓取结果，也不能成为空白占位。
- 音视频使用可访问的原生控制，不默认自动播放；播放器控件遵守原有受保护交互目标规则。
- 原始作者 HTML 的限制不因增加播放器而整体放宽。生成媒体节点的具体边界由技术设计明确。

### R5 — 静态可读与性能

- 展示块在构建时解析并生成可读 HTML；图片、组合正文和链接卡片不依赖浏览器端 Markdown/YAML 解析或组件挂载才能显示。
- 禁用 JavaScript 后，图片、组合正文、链接及原生播放器的基础能力仍存在。
- 不依靠滚动监听逐帧重算正文布局，不先隐藏正文等待进入动画或滚动触发后再恢复显示。
- 无需为图片和图文组合加载通用前端运行时；确需交互的扩展资源只由使用它的内容引入。
- 能取得图片固有尺寸或宽高比时，在加载前预留空间；资源加载、失败或播放器初始化不造成整块关联正文消失。
- 已评审的首版设计不生成缩略图或转码：本地图片发布原始字节，外部图片仍由原地址提供。通过懒加载和已知尺寸预留降低不必要的初始工作，但不保证大图的下载或解码成本；作者应提供适合展示尺寸的资源，后续可另行设计响应式变体。

### R6 — 与 Firefly 阅读体验兼容

- 相同文章在 `firefly`、`semantic` 表现及 `default`、`paper` 正文主题下均能正确阅读；局部编排不要求切换整页 presentation 或使用特定主题。
- 组合内正文继续参与现有阅读导航、查找和高亮，链接及媒体控制可正常操作。
- 块内真实标题须与文档目录和锚点语义一致；配置键、资源 URL 等不能被误当作正文标题或阅读段落。
- 技术设计必须检查摘要、索引、资源引用和 Terminal 行内阅读等既有消费者如何处理块内语义，保留它们各自既有的源文本/渲染文本约定，不能只验证单独文章页的外观。

### R7 — 作者反馈与文档

- 缺少必要字段、YAML 错误、未知 `type/layout` 等错误必须提供可定位到文档及块的诊断，不得静默丢弃内容或生成空白展示。
- 无效作者声明遵守既有严格构建校验惯例；合法声明引用的外部链接无法获取元信息，或媒体在浏览器中无法播放，与声明格式错误区分处理。
- 交付作者指南与合成示例，说明各类型最小写法、图片与文字的分组范围、移动端行为及外部查看器的代码块降级。

## 明确不在首版范围内

- 任意网站的 iframe 自动嵌入、执行作者脚本、命令或远程组件。
- 具体视频平台的嵌入播放器及账号/API 接入；可后续增加 `embed` 类型和明确的平台适配器，不能把未支持的平台页面伪装成直链播放器。
- 自动抓取所有远端网页元信息的服务、截图服务、代理、转码、上传平台或媒体资源托管系统。
- 相册、轮播、灯箱、拖拽排版、可视化编辑器、插件市场和第三方动态插件加载。
- 多图片自由画布、视频/音频与正文任意嵌套、组合块递归嵌套、正文同时环绕居中图两侧。
- 自定义 CSS/像素布局、每设备单独配置、逐帧滚动编排、背景特效和入场动画。
- 第三方网站复刻、外部系统的性能诊断或用户浏览器设置修改。
- 将现有文章整体迁移到新格式，或要求其他 Markdown 软件安装本插件。

## 后续设计与风险记录

以下是实现前需要在技术设计中回答的工程问题，不改变上述已确认的产品行为：

1. 确定解析及转换在既有高亮、HTML 清洗、X Core 身份/目录处理链中的位置，避免引入原始 HTML 旁路或让配置先进入高亮器。
2. 统一处理组合内 Markdown 与外层 Markdown 的引用、标题身份和诊断，明确不递归解析嵌套 Firefly 块。
3. 检查 YAML 中资源引用的收集与发布：它们不天然等同于 Markdown 图片节点；需要正确映射作者相对路径且不泄露主机路径或越过既有资源公开边界。
4. 明确链接卡片的无网络最小结果、播放器失败的资源入口、图片尺寸预留与浏览器格式兼容的验证办法。
5. 设计导航对组合内部正文的识别，以及主题、Terminal 行内阅读、目录和搜索的回归覆盖。
6. 验收依靠仓库内可复现的原创正文与合成媒体，不依赖外部文章、截图或临时录屏。

设计及实施交付物为 `design.md`、`implement.md` 及上下文清单。它们已随本任务实现完成；`research/pipeline.md` 保留实现前的代码库调查，`research/validation.md` 记录最终验收。
