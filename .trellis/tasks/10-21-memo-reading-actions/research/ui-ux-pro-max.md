# Memo reading actions — local UI research

## Method

The project-local UUPM skill, scripts and tables are present. CLI help confirms
`astro` support despite an older stack summary in the skill. Planning ran:

```sh
python3 .codex/skills/ui-ux-pro-max/scripts/search.py "personal memo timeline reading minimal silver white metadata clipboard actions" --design-system -p "Firefly Memo reading actions" -f markdown
python3 .codex/skills/ui-ux-pro-max/scripts/search.py "animation accessibility z-index loading clipboard feedback hover touch" --domain ux -n 3
python3 .codex/skills/ui-ux-pro-max/scripts/search.py "progressive enhancement accessible buttons responsive metadata static content" --stack astro -n 3
```

This is original task-specific synthesis, not retained third-party prose/code,
a second design-system master or browser-acceptance evidence.

## Disposition

- Keep established silver/white Memo surfaces, system font, readable spacing
  and blue accent. Generic generated dark/serif/marketing advice does not fit.
- Keep labels explicit and navigation native. Hover is an optional mouse reading
  cue; all actions work on keyboard/touch. Bodies stay selectable text.
- Make feedback local, visible, accessible and geometrically stable. Pending
  requests must not freeze unrelated entry actions; failures must be honest.
- Keep static metadata/content in Astro. Progressively enhance clipboard
  controls; preserve focus, reduced motion, 44px touch targets and header reflow.

The owner approved these choices with the final planning summary on 2026-10-21.
